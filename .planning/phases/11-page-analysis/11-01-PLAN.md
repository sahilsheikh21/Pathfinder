<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer to main IPC | Untrusted user input can request analysis modes, overrides, and question payloads |
| page DOM to service | Extracted page content may contain attacker-controlled text and sensitive values |
| service to provider SDK | External provider errors can leak implementation details if unnormalized |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | I | src/main/llm/pageAnalysisService.ts | mitigate | Apply redaction-by-default and exclude form/input values before provider requests |
| T-11-02 | T | src/shared/browser.ts | mitigate | Use strict typed request/result contracts to prevent ambiguous payload handling |
| T-11-03 | D | src/main/llm/pageAnalysisService.ts | mitigate | Add extraction stage bounds and deterministic fallback order to avoid unbounded processing |
| T-11-04 | R | src/main/llm/pageAnalysisService.ts | mitigate | Return explicit reason and userAction fields for all mapped failures |
| T-11-05 | E | src/shared/ipc.ts | mitigate | Define explicit page-analysis channels only; avoid generic privileged execution channel |
</threat_model>
